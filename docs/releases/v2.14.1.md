# v2.14.1 — spread pages no longer clip their last line

Hotfix for a rendering defect that shipped in v2.14.0 and was caught by a
reader within hours: on some double-page spreads, the last line of a page
rendered sliced in half at the bottom.

## What to test

Open a long book in **Spread** layout and page through whole chapters at a few
window widths. Every page should end on a complete line with a clean margin —
no glyphs cut mid-height at the bottom of either page. The same content should
never appear twice (end of one page and top of the next).

## Fixed

- **Spread pages could clip their last line mid-glyph.** The facing-page
  layout places a 1pt spine hairline *between* the two pages, so each page is
  half a point narrower than the paginator measured. Justified lines whose
  natural width fell inside that half-point re-wrapped at render time, pushing
  one extra line onto the page, which was then clipped. Content-dependent:
  most spreads looked fine, some clipped. Measurement and layout now share one
  width formula, spine included, with the arithmetic pinned by tests.

## Under the hood

- Dev and CI builds now report the real version (previously 0.1.0), so crash
  and feedback triage can trust the version field.
