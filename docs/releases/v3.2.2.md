# v3.2.2 — Recap one tap away, a book to start on, and no more quitting mid-Listen

Three things, one release. Readers on iPhone and iPad saw Readr disappear a
few minutes into Listen — exactly when the Readr Voice model finished its
first-use download and began speaking. Product Hunt copy promised a
spoiler-free recap the app could not yet give. And App Review met an empty
library with nothing to put in it.

## What to test

**iPhone or iPad on iOS 26.4 or later.** Fresh install: Alice's Adventures in
Wonderland is already in the library. Open it and press Listen. An Apple voice
reads from the first sentence, and keeps reading for ten minutes without the
app quitting. The voice menu shows a note explaining that Readr Voice is
unavailable on this version of iOS, no Readr Voice row, and no "downloading"
line — the ~104MB model is never requested.

**Mac on macOS 26.6 or later.** Open an English book. Readr Voice is still the
first row of the voice menu and still the default narrator.

**Stored Apple voice.** Explicitly pick an Apple voice, reopen the book, open
the voice menu: the chosen voice is checked and the unavailability note does
not appear.

**Recap, in the reader.** Read a few chapters of Alice. Next to Listen and
Ask there is a Recap button (⇧⌘R on a Mac). Press it: the Ask panel opens
with "Recap what I've read so far — no spoilers" already sent, a "Recap up to
where you are" line above it reading like "Chapter 7 of 12 · 31% · Advice
from a Caterpillar", and the answer streaming in. It names nothing from later
chapters; ask "what happens next?" and Readr declines to say. Press Done,
press Ask: a plain Ask, nothing pre-sent, with the recap as the first chip.

**Recap, from Home.** Each Continue Reading card for a text book shows
"Chapter N of M" under the Continue pill and a ✦ Recap link. Tap it: the book
opens at your place and a beat later the recap is already sent. PDF cards
show neither, and cards in a row stay level either way. On a Mac with the
reader window already open behind the library, the existing window comes
forward rather than a second one opening.

**Native PDF.** Open a PDF shown as original pages: no Recap button, no
recap chip (a PDF page is not a reading position). Switch to the reading
view in Appearance: the button appears.

**No provider.** Disconnect every provider, press Recap: the panel opens on
"No AI provider connected". Connect a key from there and press Done: the
recap sends itself.

**Sample book.** Delete the app, reinstall, launch: one book in the library,
which opens and paginates. Import another book, delete Alice, relaunch: Alice
does not come back — the seed fires once, into a never-used library only.

## Fixed

- **Readr no longer quits a few minutes into Listen on iOS 26.** Kokoro
  inference on iOS/iPadOS 26.4+ (and macOS 26.4–26.5) can terminate the
  process inside Apple's BNNS runtime (FluidAudio#817/#844) — uncatchable,
  and no compute-unit routing avoids it. On those builds Readr Voice is now
  disabled at the engine: it is not offered, not defaulted to, and its model
  is not downloaded; Apple's voices read instead and the voice menu says why.
  A stored Readr Voice preference is kept, so it returns the day the OS is
  verified safe. iOS is gated fail-closed (26.4 through every later version)
  until a device build passes; macOS 26.6+ is verified fixed and stays on.

## New

- **Recap, one tap away, and spoiler-free.** A Recap button in the reader
  toolbar (iPhone, iPad and Mac, ⇧⌘R) and a ✦ Recap action on each Continue
  Reading card open Ask with the recap already sent, under a line saying
  where it stops: "Chapter 7 of 12 · 31% · Advice from a Caterpillar". Only
  text books get it; a native PDF page is not a reading position.
- **Ask sees only what you have read.**
  Your reading position is passed with every question from a text book: the
  whole-book tier sends only the text before it, the retrieval tier drops any
  passage past it before it can be quoted or cited, and the prompt defines a
  recap as "so far, in reading order, stopping where the reader stopped" and
  forbids drawing on what the model knows of the book from elsewhere. The
  recap is also the first suggestion chip whenever there is a place to recap
  up to.
- **A book to start on.** A fresh install seeds the library with Alice's
  Adventures in Wonderland (public domain, 66KB, twelve chapters). The seed
  fires once, and only into a library that has never held a book, so it never
  reappears after you delete it. App Review notes now say so — the previous
  "ships with no books" lines were true of 3.2.1 and false of this build.

## Under the hood

- `NeuralVoiceAvailability.isCrashProneOS` (ReadrKit, table-tested) is the
  single OS gate; `KokoroSpeechEngine` starts in a new `.unsupported`
  readiness on gated builds and refuses prepare/initialize/speak itself, so
  the router's existing not-ready path does the fallback with no new checks.
- `ReadingFrontier` (ReadrKit) carries the position; `RetrievedPassage` now
  records the chapter it came from so the retrieval tier can filter.
- `ReadingPositionSummary` (ReadrKit, 24 tests) turns a `Book` and a
  `ReadingFrontier` into the "where am I" line: the chapter's own title, else
  the nearest TOC title, else "Chapter N"; N of M over linear chapters only;
  percent by character count, clamped, with a whole-chapter fallback for
  picture books.
- `AskPanelView` takes an `initialQuestion` and a `positionCaption`. The
  question is handed to `AskViewModel.sendInitialQuestionIfReady` at send
  time from `.task(id:)` and on provider change, with a once-flag in the
  model — on the iPhone simulator values captured when the sheet's storage
  is created arrived nil. `AppModel.pendingRecapBookID` is the one piece of
  plumbing from the Continue Reading card to the reader.
- Store copy no longer leads with Readr Voice on iOS; the promotional text
  and description describe Listen with Apple's voices and the recap.
