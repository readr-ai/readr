# v2.14.0 — macOS reader parity, EPUB plates, PDF search

Reading-experience release. Most of it is macOS catching up with iOS, plus two
rendering fixes that affect every book with cover art.

## What to test

**macOS reader typography.** Open a book, use the **Aa** menu in the toolbar:
typeface (New York / Charter / Georgia / Palatino / San Francisco), line
spacing, justification. None of these existed on macOS before — the controls
were built but only ever wired into the iOS appearance popover.

**Cover and title pages.** Open a book with cover art. The cover and any
volume title page should fill the page and sit centered, in both **Page/Spread**
and **Scroll** layouts — switching layout must not resize the artwork. Figures
*inside* a chapter should be unchanged: an inline ornament or icon must NOT
balloon.

**PDF search.** Open a PDF, search, press **Return**. It should jump to the
first hit. This previously did nothing at all.

**Provider settings on macOS.** Open AI providers. If you are moving from a
development build to this signed release you may see one Keychain prompt per
saved credential — that is the OS, not the app, and it is now one per credential
per launch rather than a storm. Choose **Always Allow** to stop it recurring.

## Fixed

- **macOS reader had no typeface, line-spacing or justification controls.** The
  bindings existed but were inside `#if os(iOS)`, so the Mac toolbar offered
  layout, text size and themes only.
- **Cover and title-page images rendered as postage stamps, left-aligned.**
  Publishers declare a plate at its bitmap's pixel size (a 300×413 JPEG in an
  ~860pt column) and the renderer never scaled past the declared size. A chapter
  whose entire content is one image is now presented as a plate: scaled to fill,
  centered, consistent across layouts. One book in testing had 28 such chapters.
- **Return in PDF search did nothing.** `go(to: PDFSelection)` silently no-ops
  when the layout isn't ready, which is the case while the search sheet is still
  presented. Now pages to the hit by index first.
- **Keychain prompt storm on macOS.** Provider credentials were read three or
  more times per settings refresh; with a signature/ACL mismatch each read
  raised its own dialog. Reads are now cached per launch.

## Under the hood

- The UI test suite can now run on macOS at all — the test target had no
  `Info.plist`, and the helpers assumed iOS element shapes.
- CI builds and tests with **Xcode 26**, the same toolchain TestFlight ships,
  and the iPhone job moved to **iPhone 17 Pro** (iOS 26 runtime). Previously CI
  ran Xcode 16.4 / iOS 18 and could not see the PDF search bug at all.

## Known issues

- **Books imported by older builds** may show oversized gaps between paragraphs
  and footnotes. Their stored text carries carriage-return artifacts from a
  previous parser; books imported by this build are clean. Re-importing the book
  fixes it. A guided path for this is planned — it is not automatic because
  re-parsing has to reposition existing highlights.
- **Blank facing page** after a one-page chapter in Spread layout. Chapters
  paginate independently, so a chapter with an odd page count leaves the facing
  page empty.
- **macOS UI tests run a scoped subset in CI.** Most of the suite assumes iOS
  gestures and idioms; broadening it is tracked separately.
